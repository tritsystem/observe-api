How it works

An embedding model, a real vector index, and a rerank step that admits its own limits.

Every repo is chunked at function boundaries (not fixed-size windows), embedded with stock all-MiniLM-L6-v2 — deliberately stock: a fine-tuned variant was built and measured worse on real retrieval, twice, at two different corpus sizes (see the benchmarks below) — and indexed with FAISS for the actual similarity search. A hybrid rerank blends BM25 lexical scoring into that dense-retrieved candidate pool afterward, not a naive full-corpus fusion of the two: that specific shape was chosen because it preserved cases naive fusion lost to lexical noise while eliminating cross-language contamination, measured against the alternative, not assumed.

investigate: true reframes results as unverified candidates with a falsification hint instead of ranked answers — a semantic match is correlation with a query, not proof a location causes whatever an agent is actually investigating. And this isn't only reachable over raw HTTP: a real A2A endpoint (agent card + message:send, not just a discovery manifest) sits alongside the MCP server and LangChain/CrewAI tools, so another agent can find and call this one without a human wiring up the integration first.

New — agentic commerce

Also routes AI-agent buyers to real sellers. Never touches a payment.

The Agentic Commerce Protocol (OpenAI + Stripe) defines checkout between one buyer-agent and one already-known merchant — its own spec has no seller_id field at all, and explicitly leaves multi-seller discovery to "the marketplace layer above this API." That layer doesn't really exist yet as a standard. This is a real, working implementation of it: a seller registers a real ACP checkout_session_url and a listing feed; a buyer-agent describes what it wants in plain language; matching reuses this same search engine. The match returned is the seller's own endpoint — the buyer's agent calls it directly to actually transact. This service never sees payment credentials, never proxies checkout, never holds funds.

Ranking also learns: a real Spikeling spiking-neuron network (not a counter) gives each buyer key its own memory of which listings keep getting returned or actually purchased, persisted across restarts. Two real bugs were caught by testing this against the live server rather than only a mocked suite — one where a strong "confirmed purchase" signal could self-erase via the same threshold-crossing mechanism that makes the neuron fire — both fixed and now covered by regression tests. Honestly disclosed, not hidden: purchase feedback is self-reported by the buyer's own agent, not independently verified against the seller's real transaction, since this service deliberately never sees it.

Pricing

Priced under what a search saves, not around what it costs to run.

$5 / 50,000 credits
≈ $0.0001 per search 1 credit deducted per call, refunded automatically on a failed search

A search's own marginal compute cost is close to zero — one embedding and a matrix multiply against a model that's already warm in memory. The real constraint isn't infrastructure, it's whether querying beats the token cost of not querying. At typical model API pricing, a few thousand tokens saved is worth a fraction of a cent — so the price per call is set to clearly undercut that, not to price the compute.

New keys start with a small free trial balance, so you can run real queries before buying credits. Indexing a repo of your own via /v1/private/index costs substantially more per repo than a single search — it's a real one-time compute cost (cloning and embedding an entire codebase), not a marginal query.
